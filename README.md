# Fraud Triage Dashboard with LLM-Written Alert Summaries — Template Version

Python, LightGBM, Streamlit — built from scratch, locally.
**Alert summaries in this repo are template-generated, NOT LLM-written.**
See "LLM" section below.

## Data actually used — read this first
**NOT IEEE-CIS.** The original brief named IEEE-CIS Fraud Detection
(590K+ transactions), but IEEE-CIS is Kaggle-gated and no Kaggle
credentials were available, so it was NOT downloaded and is NOT claimed
here. See DATA_SOURCES.md for the full substitution note.

Data actually used:
- **Synthetic transactions** generated by `src/generate_data.py`
  (seed 42), mimicking IEEE-CIS schema: amount, product code,
  card/user, device, email domain, timestamp.
- 60,000 transactions over 90 synthetic days, 8,000 synthetic users.
  Overall fraud rate in the synthetic data: **4.70%**.
- File: `data/transactions.csv` (featured data, 8.5 MB).
  `data/transactions_raw.csv` is regenerated by train.py if missing
  and is not required for upload.
- Fraud labels are generated by the documented risk rule in
  `src/generate_data.py`. They are NOT real fraud labels.

## Results — all computed by src/train.py on 2026-11-04 (see outputs/metrics.json)
- Split: **chronological** 70% train / 15% validation / 15% test
  (not random — a random split would make "alerts per day" meaningless).
  Train: 42,000. Validation: 9,000. **Test: 9,000** (last ~13.5 days).
  Test fraud rate: **5.21%**.
- Model: **LightGBM** (300 trees). No XGBoost in this project.
- ROC AUC (test): **0.652**
- PR AUC / average precision (test): **0.104**
- Cost-based threshold, chosen on validation only:
  missed-fraud cost = transaction amount, false-alarm cost = $20.
  Threshold: **0.0558**. At that threshold on test:
  precision **10.09%**, recall **34.12%**.
- **Precision at fixed analyst capacity: 10.45% at 100 alerts/day.**
  Test period: 13.49 days, so K = 1,349 top-scored test alerts.
  Recall at that capacity: **30.06%**.
  For context, precision@capacity is 2.01× the test base rate
  (10.45% / 5.21%) — a computed lift, not a claimed improvement
  over any prior system.
- Velocity features (prior transactions only, no leakage):
  count/sum in 1h, 24h, 7d per user, time since last transaction,
  amount vs user prior mean (clipped to [-10, 10]), night flag,
  log amount, plus one-hot product/device/email/card.

## LLM — what is and is not true here
- **NOT true:** that summaries were written by an LLM.
- **True:** summaries are generated by `src/narrative.py`, a
  template/rule-based generator grounded in each transaction's
  amount, velocity, device, hour and product values, listing its
  top factors explicitly.
- `src/llm_client.py` is a **disabled stub**: it returns None unless
  `LLM_API_KEY` is set, and even then it raises NotImplementedError
  until a provider call is implemented. No LLM was called in this run.
- Human review: **none was conducted, and no review accuracy
  percentage is claimed.** `docs/human_review_protocol.md` describes
  how a future review would be rated, and `docs/review_template.csv`
  is an empty template for that review.

## How to run
```bash
pip install -r requirements.txt
python src/generate_data.py   # optional; data is already included
python src/train.py           # writes outputs/metrics.json + charts + alerts
streamlit run dashboard/app.py
```
The dashboard reads `outputs/metrics.json` and
`outputs/alerts_sample.csv` (top 200 test alerts by score, with
template narratives).
