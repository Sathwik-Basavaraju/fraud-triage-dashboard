# Data Sources — Fraud Triage Dashboard

## Data actually used
- **Synthetic transactions generated by src/generate_data.py**
  - Rows: 60,000 synthetic transactions over 90 days (2024-01-01 to
    2024-03-31, synthetic dates), 8,000 synthetic users.
  - Schema mimics IEEE-CIS Fraud Detection (transaction amount,
    product code, card/user identifiers, device and email-domain
    fields, timestamp), with velocity features computed in
    src/features.py from prior transactions only.
  - Fraud labels are generated by the documented risk rule in
    src/generate_data.py (seed 42). They are NOT real fraud labels.
  - Files in this repo: `data/transactions.csv` (featured data,
    8.5 MB). `data/transactions_raw.csv` is regenerated by
    src/train.py if missing and is not required for upload.
  - Reproduce it: `python src/generate_data.py`, then
    `python src/train.py` (which recomputes features).

## Data NOT used, and why
- **IEEE-CIS Fraud Detection (590K+ transactions)** — the dataset
  named in the original project brief — was NOT used.
  - Reason: IEEE-CIS is distributed via Kaggle, which requires
    Kaggle authentication. No Kaggle credentials were available in
    the build environment, so the dataset could not be downloaded
    without auth, and no IEEE-CIS file, schema detail beyond the
    public field names mimicked here, or figure is claimed.
  - Substitution: synthetic transactions with a similar shape,
    clearly labelled as synthetic in README.md, code, and dashboard.
  - Consequence: every metric in outputs/metrics.json is computed
    on the synthetic data, NOT on IEEE-CIS, and no IEEE-CIS figure
    is reproduced.

## No other data
No real transaction, customer, or payment data is used. All user
IDs, amounts, and labels in this repo are synthetic.
